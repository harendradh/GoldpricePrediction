# Coding Standards — df-dbx-rt-ingestion-workflow

These standards are enforced by CI (ruff, mypy, pytest) and code review.
They exist to keep thousands of applications consistent and to maximize the
quality of AI-assisted (Copilot) code generation.

## Language & typing
- Python 3.10+; `from __future__ import annotations` in every module.
- Full type hints on all public functions and methods; `mypy --strict` clean.
- PySpark imports only inside methods or under `TYPE_CHECKING` — modules must
  import without a Spark runtime.

## Naming conventions
| Thing | Convention | Example |
|---|---|---|
| Package/module | `snake_case` | `fixed_width_parser.py` |
| Class | `PascalCase` | `FixedWidthParser` |
| Registry name | `snake_case` | `fixed_width` |
| Platform registry name | `<platform>.<name>` | `platform_a.account` |
| App spec name | `kebab-case` | `gbs-auth-platform-a` |
| Pipeline/query name | `<app>__<topic_safe>` | generated by `PipelineContext` |
| Framework columns | `_dfx_*` prefix | `_dfx_error` |
| Error codes | `DFX-<module><nn>` | `DFX-4000` |
| Env-var secrets | `<SCOPE>__<KEY>` | `DFX_MONITORING__API_TOKEN` |

## Design (SOLID / clean architecture)
- **Open/Closed:** new behavior = new registered class. `if type == ...`
  dispatch chains are rejected in review.
- **Single responsibility:** sources read, parsers parse, sinks write; the
  builder wires, the runner supervises. Do not blur these.
- **Dependency direction:** `core` depends on nothing; everything depends on
  `core`. Platform packages depend on `common`, never on each other.
- **Explicit contracts:** ABCs in `core/interfaces.py`; docstrings state the
  contract (inputs, outputs, error behavior), not the implementation.

## Error handling
- Raise the most specific `FrameworkError` subclass with `context={}` detail.
- Data problems are not exceptions: set `_dfx_error`, let the DLQ handle it.
- Observability code (listeners, publishers, audit) must catch its own
  exceptions — never fail the stream.

## Logging
- Use `core.logging.get_logger(<area>)`; structured fields via
  `extra={"dfx": {...}}`. No print(), no f-string secrets, no payload dumps.

## Testing standards
- Unit tests are Spark-free wherever possible; Spark tests use
  `pytest.importorskip("pyspark")` and the `spark` marker.
- Integration tests (real Kafka/Databricks) carry the `integration` marker
  and are excluded from PR CI.
- Every parser needs: happy path, malformed record → `_dfx_error`, envelope
  preservation.
- Coverage gate: 80% on `src/dbx_rt_ingestion` (excluding templates).

## Security
- Secrets only via `${secret:scope/key}`; scanned in review and CI.
- No dynamic `eval`/`exec`; SQL built from spec values must be identifier-
  validated (pydantic patterns) — never interpolate free user input.
- Dependencies pinned by range in `pyproject.toml`; supply-chain scanning in CI.

## Git & review
- Conventional commits (`feat:`, `fix:`, `docs:`...). One extension point or
  one platform per PR. ADR required for architectural changes
  (`docs/adr/`). Two approvals for framework core; platform owners approve
  their platform packages.
